# Entity Resolution Dataset Documentation

## 1. Project Overview

This project prepares business/entity records from multiple source datasets for supervised entity-resolution (record-matching) using machine learning.

The goal is to identify whether a business record from **Source 2 or Source 3** corresponds to a business record from **Source 1**.

---

## 2. Source Datasets

| Dataset | Description |
|---|---|
| `train_source1.tsv` | Reference/source-1 business entities |
| `train_source2.tsv` | Noisy/duplicate business entities from Source 2 |
| `train_source3.tsv` | Noisy/duplicate business entities from Source 3 |
| `ground_truth.tsv` | Known mappings between Source 1 and matching Source 2/Source 3 entities |

Source 1 is treated as the reference dataset. Source 2 and Source 3 are combined as candidate matching records.

---

## 3. Data Cleaning

The following cleaning operations were applied to Source 1, Source 2 and Source 3:

- Removed whitespace from column names.
- Normalized Unicode text using NFKC normalization.
- Converted text to case-insensitive form using `casefold()`.
- Replaced `&` with `and`.
- Removed punctuation while preserving Unicode letters/numbers.
- Normalized repeated whitespace.
- Created cleaned business names and addresses.
- Removed common legal/business suffixes from names.
- Standardized common address abbreviations such as:
  - `st` → `street`
  - `rd` → `road`
  - `ave` / `av` → `avenue`
  - `blvd` → `boulevard`
  - `ln` → `lane`
  - `dr` → `drive`
  - `apt` → `apartment`
  - `ste` → `suite`
  - `hwy` → `highway`
- Extracted numeric parts from addresses.
- Created sorted-token versions of names and addresses.
- Created basic length and word-count features.
- Created missing-value indicators.
- Removed only exact duplicate rows.

The cleaning process was designed to preserve multilingual/Unicode business names rather than restricting the data to English characters.

## 6. Training Dataset Construction

The ground truth was converted into positive entity pairs.

A positive pair means:

```text
Source 1 entity ↔ known matching Source 2/Source 3 entity
```

For each positive pair, a label of `1` was assigned.

Negative pairs were then generated by randomly selecting candidate Source 2/Source 3 entities that were **not** known matches for the corresponding Source 1 entity.

Negative pairs were assigned label `0`.

The resulting dataset contains approximately equal numbers of positive and negative examples.

---

## 10. Recommended Next Step

Before model training, split the data by `source1_entity_id` rather than randomly splitting individual rows.

This prevents the same Source 1 entity from appearing in both training and testing data and helps avoid data leakage.

The next stage is:

```text
training_data.csv
        ↓
Group-based Train/Test Split
        ↓
ML Model Training
        ↓
Validation / Evaluation
        ↓
Match Prediction
```
